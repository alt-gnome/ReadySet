Ready Set — модульное GTK-приложение. Последовательность его страниц собирается
из плагинов шагов, а параметры можно передать заранее в конфигурации, не
заставляя пользователя повторно вводить уже известные значения.

## Доступные шаги

- [дата и время](plugins/date-and-time/README.ru.md)
- [клавиатура](plugins/keyboard/README.ru.md)
- [язык](plugins/language/README.ru.md)
- [лицензионное соглашение](plugins/license-agreement/README.ru.md)
- [сеть](plugins/network/README.ru.md)
- [приватность](plugins/privacy/README.ru.md)
- [программное обеспечение](plugins/software/README.ru.md)
- [пользователь](plugins/user/README.ru.md) — собирается как `user-passwdqc`
  (по умолчанию) и/или `user-pwquality` в зависимости от опции сборки
  `password_check_backend`

Если первым выбранным шагом не реализован интерфейс `Welcome`, Ready Set
показывает собственную приветственную страницу.

Плагины установщика загружаются отдельно через `--installer`; их шаги имеют
префикс `installer.`, например `installer.example-step`.

## Режимы работы

Режим определяется автоматически:

- `installer` — указан плагин установщика через `--installer`;
- `initial-setup` — приложение запущено от имени `ready-set` или
  `gnome-initial-setup`;
- `existing-user` — приложение запущено от имени обычного пользователя.

В сборках с `-Dnightly=true` режим можно принудительно задать
`--force-mode`.

## Конфигурация

Настройки передаются аргументами командной строки или key-файлом; аргументы
командной строки имеют приоритет. Параметры приложения находятся в группе
`[Application]`, значения контекста плагинов — в `[Context]`. Значения из
`[Context]` и `--context` блокируются: интерфейс не сможет заменить значение,
которое централизованно передала конфигурация.

Используется только первый найденный файл, значения из нескольких файлов не
объединяются:

1. Файл из `--conf-file`.
2. `/etc/ready-set/config`.
3. `/usr/share/ready-set/config`.

Пример находится в [example/example.conf](example/example.conf). Параметры
отдельных плагинов описаны в их README.

### Основные опции

| Опция | Назначение |
| --- | --- |
| `--apply-only` | Применить конфигурацию без запуска интерфейса; недоступно в `existing-user`. |
| `--can-close` | Всегда разрешить закрытие окна. |
| `--conf-file=ФАЙЛ` | Использовать указанный файл конфигурации. |
| `--context=КЛЮЧ=ЗНАЧЕНИЕ` | Передать значение контекста; опция может повторяться. Списки строк разделяются запятыми. |
| `--force-layout=ТИП` | Задать `big`, `small` или `vertical`; обычно выбирается автоматически. |
| `--fullscreen` | Запустить окно во весь экран. |
| `--height=ВЫСОТА`, `--width=ШИРИНА` | Задать размер окна; по умолчанию 800×1000. |
| `--installer=ПЛАГИН` | Выбрать плагин установщика. |
| `--resizable` | Разрешить изменять размер окна. |
| `--sandbox` | Выполнить сценарий без изменений в системе. |
| `--steps=СПИСОК` | Список модулей шагов через запятую. |
| `--version` | Вывести версию и завершиться. |

`--force-mode` доступна только в nightly-сборках.

## Команды

- `generate-bash-completion` — вывести скрипт автодополнения Bash.
- `nothing-to-do` — вывести `0` в стандартный поток ошибок, если настройка не
  требуется, или `1` в противном случае.

## Тестирование и сборка

Для безопасной проверки сценария используйте `--sandbox`. После настройки
сборки тесты запускаются так:

```sh
meson setup _build
meson compile -C _build
meson test -C _build
```

Все параметры Meson перечислены в [meson.options](meson.options).
